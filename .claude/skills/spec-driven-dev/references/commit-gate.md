# 커밋 포인트 & 스톱 게이트 (Phase 3~5)

커밋 타이밍 보존 규칙. 오케스트레이터는 **첫 커밋 포인트에 도달하기 전에** 이 문서를 읽고
그대로 적용한다 — MSG-206 커밋 유실 재발 방지 규칙이라 요약본으로 대체하지 않는다.

- **커밋 포인트 제안 (중간중간, 필수)**: 모듈이 green + 리뷰를 통과할 때마다 리더는 그 시점의
  파일 목록과 `MSG-{번호} {타입}: {요약}` 메시지로 커밋 포인트를 **즉시 사용자에게 알린다** —
  끝나고 몰아서 한 커밋 금지(성민 선호: 작은 커밋 누적, 2026-07-22 지시). Phase 4의 리뷰 반영
  라운드가 델타 검증을 통과한 시점, Phase 5의 문서 정리 시점도 각각 커밋 포인트다.
  커밋 실행은 항상 사용자 몫이다.
  **구현이 한 에이전트 런에 몰린 경우에도 몰아 커밋 금지 (2026-07-24 지시)** — 개발 에이전트가
  여러 모듈을 한 번에 완성해 중간 포인트가 없었으면, 리더가 사후에라도 레이어/모듈 단위
  (엔티티·리포지토리 → 서비스·DTO → 컨트롤러 → 문서, 각 단계 독립 컴파일 순서)로
  **경로 스테이징 커밋 계획을 쪼개 제안**한다. 파일 수가 3~4개를 넘는 단일 커밋 제안은 그 자체가
  신호다 (MSG-222에서 17파일 1커밋 제안 → 지적받음, 2026-07-24).

- **커밋 포인트 스톱 게이트 (2026-07-23 지시)**: 커밋 포인트를 알린 뒤에는 사용자가 커밋 완료를
  응답할 때까지 **새 단계 착수를 보류한다** — 다음 모듈 지시, 다음 Codex/리뷰 라운드, 문서 정리
  모두 금지. 이미 백그라운드에서 실행 중이던 작업의 결과를 수신·보고하는 것만 허용한다.
  단, **커밋 대상 파일을 수정 중인 에이전트가 아직 실행 중이면 커밋 포인트 알림 자체를 그 에이전트
  완료 후로 미룬다** — 사용자가 스테이징하는 도중 파일이 계속 바뀌면 게이트가 무의미하다. 실행 중인
  작업이 커밋 대상과 무관한 파일만 만질 때만 즉시 알린다.
  배경: 오토모드에선 백그라운드 알림이 턴을 계속 이어가 커밋 포인트가 여러 개 쌓이고, 워킹트리에
  다음 단계 변경이 겹치면 파일 단위 스테이징이 꼬인다(MSG-206). 사용자가 "계속/스킵"이라고
  응답하면 커밋 없이 진행한다.
