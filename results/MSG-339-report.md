# MSG-339 AI 전용 서버 분리와 처리량 실측

2026-08-07, 서울 리전의 전용 t3.small에서 측정했다.

**결론: 서버 분리는 완료했지만 배치 추론[^1]으로 속도와 처리량을 높이는 목표는 달성하지 못했다.**
배치 2와 4가 기준보다 각각 4.34%, 3.94% 느렸다. 스펙의 단계별 게이트에 따라 워커 2는
실행하지 않았고, 배포값은 `AI_WORKERS=1`, `AI_BATCH_SIZE=1`로 확정했다.

원자료:

- 단일 3회 요약: `results/MSG-339-bench-summary.json`
- 검출 상자 비교: `results/MSG-339-detections.json`
- 동시 6건 통과 결과: `results/MSG-339-load-w1b1-clean/`
- 잔여 스왑이 있던 첫 측정: `results/MSG-339-load-w1b1-stale-swap/`
- CloudWatch 요약: `results/MSG-339-cloudwatch.json`

## 판정

| 항목 | 기준 | 결과 | 판정 |
|---|---:|---:|---|
| AI 서버 분리 | BE와 다른 전용 EC2에서 실행 | BE는 새 사설 주소로 호출, 기존 AI 컨테이너 중지 | 통과 |
| 단일 처리 시간 | 배치 1보다 20% 이상 단축 | 배치 2는 4.34% 증가, 배치 4는 3.94% 증가 | 실패 |
| 검출 동등성 | 얼굴과 번호판 상대 recall[^2] 1.000 | 배치 2와 4 모두 얼굴 1.000, 번호판 1.000 | 통과 |
| 처리량 1.7배 | 워커 2와 채택 배치 비교 | 단일 시간 게이트 실패로 워커 2 미실행 | 미달성 |
| 동시 6건 안정성 | 전 건 완료, 연속 스왑 I/O[^3] 3회 미만, OOM·재시작 0 | 6건 완료, 연속 2회, OOM·재시작 0 | 통과 |
| API 계약 | 경로, 필드, 상태 전이 유지 | 변경 없음 | 통과 |

이 티켓으로 확인한 개선은 자원 격리다. 기존 BE 인스턴스에서 PostgreSQL, Redis, Kafka,
인코딩과 AI 추론이 같은 2vCPU와 메모리를 다투지 않는다. 블러 한 건의 처리 시간 단축과 AI 자체
처리량 향상은 입증하지 못했다.

## 전용 인스턴스

| 항목 | 값 |
|---|---|
| EC2 | `i-0b5828e26d4bc7dec`, t3.small, Ubuntu 24.04, `ap-northeast-2a` |
| 네트워크 | 기존 VPC와 서브넷, 사설 IP `10.0.1.45` |
| 저장 공간 | 암호화한 gp3 20GB, 3,000 IOPS, 125MB/s |
| 스왑 | `/swapfile` 2GB, `/etc/fstab`에 등록 |
| CPU 크레딧[^4] | unlimited |
| 보안 그룹 | 8000은 BE 보안 그룹만 허용, 22는 `0.0.0.0/0` |

22 포트 공개는 GitHub 호스팅 러너의 주소가 고정되지 않는 현재 SSH 배포 방식에 따른 제약이다.
비밀번호 인증과 root 로그인을 막고 키 인증만 허용했다. 8000 포트는 공인 인터넷에 열지 않았다.

cloud-init은 `/run/sshd`가 생기기 전에 `sshd -t`를 실행해 한 번 `error`로 끝났다. 디렉터리를
만든 뒤 설정 검증과 SSH 재적재를 직접 통과시켰다. 스왑, Docker, 컨테이너 헬스도 다시 확인했다.

## 배치 크기 비교

29초 `crowd` 영상을 배치별로 3회 처리했다. 최초 모델 다운로드는 제외하고 작업별 모델 로드는
포함했다. 20% 단축 기준은 144.42초 이하다.

| 배치 | 실행 시간 | 중앙값 | 기준 대비 | 피크 메모리 | 판정 |
|---:|---|---:|---:|---:|---|
| 1 | 180.53, 181.08, 180.05초 | 180.53초 | 기준 | 503.7MB | 기준값 |
| 2 | 188.37, 192.40, 186.72초 | 188.37초 | 4.34% 느림 | 545.1MB | 기각 |
| 4 | 187.64, 186.12, 191.13초 | 187.64초 | 3.94% 느림 | 615.5MB | 기각 |

검출 비교는 `crowd`, `plates`, `kr-faces`, `kr-plates`에서 각 30프레임을 사용했다. 배치 1이
찾은 얼굴 710개와 번호판 51개를 배치 2와 4가 모두 맞췄다. 정확도는 유지됐지만 호출 횟수를
줄인 이득보다 여러 프레임을 함께 전처리하는 비용과 메모리 증가가 컸다.

단일 시간 기준을 통과한 배치가 없으므로 워커 2 부하는 실행하지 않았다. 속도에 실패한 설정으로
처리량 실험을 이어가면 스펙의 게이트를 어기고 더 많은 CPU 크레딧만 쓰게 된다.

## 워커 1 동시 6건 기준선

`AI_WORKERS=1`, `AI_BATCH_SIZE=1`에서 같은 29초 영상을 6건 동시에 제출했다.

| 항목 | 결과 |
|---|---:|
| 완료 | 6/6 `DONE`, 작업 유실 0 |
| 총 소요 | 1,415초, 23분 35초 |
| 처리량 | 15.27건/시간 |
| 작업별 `PROCESSING` | 226초에서 244초, 중앙값 236.5초 |
| 최대 큐 대기 | 1,189초 |
| 메모리 | 사용 1,373MB, 가용 최저 534MB |
| 스왑 | 실행 직전 수동 확인 0MB, 첫 10초 표본 13MB, 피크 65MB, 연속 I/O 피크 2회 |
| load1 | 피크 3.56 |
| 결과 영상 | 6개 모두 H.264, 29.029초, 8,985,532바이트 |
| 컨테이너 | 재시작 `0→0`, `OOMKilled=false→false` |

첫 측정은 앞선 배치 벤치 9회가 남긴 스왑 480MB에서 시작했다. 연속 스왑 I/O가 9회라 실패했지만
부하 자체와 이전 실험의 잔여 상태를 구분할 수 없었다. `swapoff`와 `swapon`으로 0MB를 확인한 뒤
같은 설정을 다시 측정했고 연속 I/O는 2회로 통과했다. 첫 실패도 재현 조건과 함께 보존했다.

MSG-151의 시간당 20건에서 23건과 이번 15.27건은 직접 비교하지 않는다. MSG-151은 BE가 인코딩한
720p 입력을 AI에 전달했고, 이번 스크립트는 원본 클립을 AI API에 바로 제출했다. 이번 수치는
후보 설정을 같은 입력에서 비교하기 위한 전용 기준선이다.

## CPU 크레딧과 비용

모든 벤치와 부하가 끝난 뒤 CloudWatch에서 확인한 값은 다음과 같다.

| 지표 | 결과 |
|---|---:|
| `CPUUtilization` | 관측 최대 96.88%, 마지막 5분 평균 59.83% |
| `CPUCreditBalance` | 0 |
| `CPUSurplusCreditBalance` | 70.686 |
| `CPUSurplusCreditsCharged` | 0 |

unlimited 모드는 잔액이 0이어도 성능을 기준선으로 제한하지 않는다. 24시간 안에 surplus를
갚지 못하면 추가 요금이 생긴다. 이번 관측 시점의 실제 과금 지표는 0이지만, 70.686크레딧이
전부 과금되면 약 0.0589달러다. AWS는 T3 Linux surplus를 vCPU 시간당 0.05달러로 계산한다
([EC2 온디맨드 요금](https://aws.amazon.com/ec2/pricing/on-demand/),
[unlimited 동작](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/burstable-performance-instances-unlimited-mode-concepts.html)).

AWS가 2026-08-06에 게시한 [서울 리전 가격표](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonEC2/current/ap-northeast-2/index.csv)와
[VPC 가격](https://aws.amazon.com/vpc/pricing/)을 사용했다. 한 달은 730시간으로 계산했다.

| 항목 | 단가 | 월 예상 |
|---|---:|---:|
| t3.small Linux 온디맨드 | 0.026달러/시간 | 18.98달러 |
| gp3 20GB | 0.0912달러/GB-월 | 1.824달러 |
| 공인 IPv4[^5] 1개 | 0.005달러/시간 | 3.65달러 |
| 기본 합계 |  | **24.454달러/월** |

CPU surplus, 인터넷 데이터 전송, 세금은 기본 합계에 넣지 않았다. surplus는 실제 24시간 사용률에
따라 달라지므로 짧은 벤치 한 번을 월 비용으로 늘리지 않는다.

## 배포 상태

- GitHub Actions의 `DEV_EC2_HOST`를 새 EIP로 바꿨고 `DEPLOY_ENABLED=true`를 확인했다.
- BE의 `AI_BASE_URL`을 `http://10.0.1.45:8000`으로 바꾼 뒤 애플리케이션 200 응답과 AI
  `/health` 연결을 확인했다.
- 기존 BE 인스턴스의 `fillmap-ai` 컨테이너는 중지했다. 종료 코드는 137이었고 OOM은 아니었다.
- 새 AI 인스턴스의 배포 검증은 실영상 2건이 모두 `DONE`이고 H.264로 읽히는 것까지 통과했다.

현재 설정과 롤백 설정은 같다.

```dotenv
AI_WORKERS=1
AI_BATCH_SIZE=1
```

처리량을 더 높여야 할 때는 실제 업로드가 시간당 20건 이상으로 유지되는지 먼저 확인한다.
그때는 이 t3.small에서 워커 수를 올리기보다 고정 CPU 성능이나 수평 분리를 비용과 함께 다시 비교한다.

[^1]: 배치 추론은 여러 프레임을 묶어 모델 호출 한 번에 넘기는 방식이다. 호출 횟수는 줄지만 CPU 전처리와 메모리 사용량이 늘 수 있다.
[^2]: 상대 recall은 배치 1이 찾은 상자를 후보 배치가 얼마나 다시 찾았는지 나타낸다. 두 상자의 IoU가 0.5 이상이면 같은 대상으로 셌다.
[^3]: 스왑 I/O는 메모리 페이지를 RAM과 디스크 사이에서 옮기는 작업이다. 연속되면 디스크 대기로 처리 시간이 흔들릴 수 있다.
[^4]: CPU 크레딧은 t3 계열이 기준 CPU 성능을 넘겨 쓸 때 소비하는 값이다. unlimited에서는 잔액이 없어도 버스트하지만 24시간 평균이 기준을 넘으면 요금이 붙을 수 있다.
[^5]: 공인 IPv4에는 실행 중인 EC2에 연결한 EIP도 포함된다. AWS는 사용 중인지와 상관없이 시간당 0.005달러를 부과한다.
