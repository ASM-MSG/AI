# MSG-280 — 번호판 블러가 글자를 못 지우던 문제

**결론: 블러 커널 기준을 ROI 짧은 변 → 긴 변으로 바꿔 해결.** 탐지는 처음부터 정상이었고,
마스킹 강도만 부족했다. 감지 건수·처리 시간 회귀 없음.

원자료: `results/MSG-280-blur.json`

## 증상

블러 처리가 끝난(READY) 영상에서 번호판 글자가 그대로 읽힌다. 미탐지가 아니라 **"가린 척"**이라
더 위험하다 — 파이프라인은 정상 완료로 보고한다.

한국 블랙박스 클립(`kr-plates.mp4`, 30초)의 정면·정지·근접 번호판이 세 구간(14s·20s·26s)
모두 판독 가능했다. 가장 유리한 조건에서 실패한 것이다.

## 원인 — 커널이 짧은 변 기준

`bench.py`의 `blur_boxes()`:

```python
k = max(3, (min(roi.shape[:2]) // 4) | 1)   # 수정 전
```

번호판 박스는 납작하다(실측 111×32px). 짧은 변 32를 기준으로 잡으면 `k=9`가 되고,
9px 가우시안 커널은 번호판 글자 굵기를 못 넘어 글자가 살아남는다.

얼굴 박스는 대체로 정사각형이라 짧은 변으로 잡아도 커널이 충분히 커진다.
**박스가 납작할수록 블러가 약해지는 구조**였고, 그 편향이 정확히 번호판에만 걸렸다.

한국 번호판 특수성이 아니다. 커널 계산은 입력과 무관하며, 기존 서양 샘플
`plates.mp4`(111×57px, `k=15`)도 같은 상태였다.

같은 프레임에 번호판 모델을 직접 물려 확인한 결과 **conf 0.49로 정확히 잡고 있었다** —
탐지 계층은 무결하다. conf를 0.001까지 낮추거나 `imgsz`를 1920까지 올려도 박스는 그대로였다
(오히려 conf만 올라감: 0.49 → 0.72). 즉 탐지 쪽에 손댈 이유가 없었다.

## 수정

```python
k = max(3, (max(roi.shape[:2]) // 4) | 1)   # 수정 후
```

| 대상 | 박스 | 수정 전 k | 수정 후 k | 판독 |
|------|------|----------|----------|------|
| `kr-plates.mp4` | 111×32px | 9 | 27 | 읽힘 → 불가 |
| `plates.mp4` | 111×57px | 15 | 27 | (원본이 이미 저화질) → 불가 |

픽셀레이트(모자이크) 전환도 비교했으나 변경 폭 대비 이득이 없어 기각했다 — 긴 변 기준
가우시안으로 글자가 완전히 소거된다.

## 검증

### 수치 (macOS mps — 정확도 판단용, 시간 절대값은 무효)

| 영상 | 감지 (얼굴/번호판) | mask 단계 | 전체 |
|------|-------------------|-----------|------|
| `kr-plates` 전 | 185 / 628 | 0.019s (0.1%) | 22.05s |
| `kr-plates` 후 | 185 / 628 | 0.065s (0.3%) | 22.14s |
| `kr-faces` 전 | 5985 / 145 | 0.134s (0.5%) | 27.19s |
| `kr-faces` 후 | 5985 / 145 | 0.263s (1.0%) | 26.75s |

- **감지 건수 완전 동일** — 탐지 계층을 건드리지 않았음을 확인.
- mask 단계는 커널이 커져 약 2배가 되지만 전체의 1% 미만이라 처리 시간은 사실상 불변.
  (EC2 실측은 필요 없다고 판단 — 병목은 추론 ~80%이고 mask는 원래 1% 미만이다)

### 육안

`samples/kr-check/`에 원본·수정 전·수정 후 3단 비교 이미지를 남겼다(`samples/`는 gitignore).
얼굴은 수정 전후 동일하게 블러되며 과블러도 없다.

## 왜 지금까지 안 걸렸나

두 가지가 겹쳤다.

1. **육안 검증이 얼굴 위주였다.** MSG-142(측정)·MSG-158(얼굴 conf 실험) 모두 초점이 얼굴이었고,
   얼굴은 이 버그의 영향을 받지 않는다.
2. **샘플이 전부 서양 스톡 영상이었다.** `crowd`·`normal`·`plates`·`hires` 4개 모두 Pexels다.
   그중 유일한 번호판 샘플 `plates.mp4`는 원본 해상도가 낮아 번호가 원래 식별 불가 수준이라,
   블러가 약해도 결과 화면상 티가 나지 않았다.

즉 **번호판을 판독 가능한 화질로 담은 샘플이 레포에 하나도 없었다.**

## 남는 것

- 한국 번호판·한국인 얼굴 샘플은 로컬(`samples/kr-*.mp4`)에만 있고 커밋되지 않는다.
  회귀 검증을 재현하려면 클립을 다시 받아야 한다 — 출처는 `results/MSG-280-blur.json`의
  `samples` 항목에 남겨두었다.
- dev에 배포된 버전은 이 버그를 갖고 있다(MSG-168 개통 이후 처리분 전체).
  이미 READY로 넘어간 영상의 재처리 여부는 제품 판단 사항.

## 재현

```bash
python bench.py --smoke                                   # 납작한 박스 커널 검증 포함
python bench.py samples/kr-plates.mp4 --device mps --out out.mp4
```

`--smoke`에 30×120 ROI(15px 폭 블록 = 번호판 글자 굵기 근사) 검증을 추가했다.
짧은 변 기준으로 되돌리면 잔여 std가 0.91배에 머물러 assert가 걸린다(긴 변 기준은 0.65배).
