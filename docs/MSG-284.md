# MSG-284: 무의미 영상 프리체크

> 요구사항 정본: `docs/prd/MSG-284-prd.md` (상태: 검토됨) · 판정 규칙 근거: `results/MSG-284-report.md`
> 이 문서는 PRD의 FR/비기능에 "어떻게"만 붙인다. PRD와 어긋나는 서술이 있으면 PRD가 이긴다.

## 개요

암흑·렌즈 가림 영상을 얼굴·번호판 추론 **전에** 걸러 큐 점유와 사용자 대기를 없앤다.
판정은 grayscale 대비(std)의 프레임 중앙값 하나로 하고, 탈락 잡은 추론·하이라이트·재인코딩을
전부 건너뛴 채 `DONE` + `highlights=[]` + `precheck={passed:false, reason}`으로 끝낸다.
블러본을 만들지 않으므로 `GET /jobs/{id}/video`는 409다(원본 유출 차단).

## 배경 · 목표

처리 가치가 없는 영상도 정상 영상과 똑같이 건당 ~187초를 쓴다(`results/ec2-aarch64-2core-crowd.json`).
추론이 전체의 87.4%인데, 추론 자체를 빠르게 하는 소프트웨어 레버는 이미 소진됐다 —
OpenVINO +5%(MSG-207), 프레임 스킵 커버리지 46% 붕괴(MSG-207), imgsz 하향 recall 붕괴(MSG-281).
남은 방향은 "애초에 처리할 영상을 줄이는 쪽"이고 이 티켓이 그것이다.

목표(PRD §2):
- 암흑·렌즈 가림 영상이 추론 없이 판정되고 해당 잡이 **5초 이내**로 끝난다(현재 ~187초).
- 정상 영상 **오탐 0** — 커밋 샘플 4종 + 한국 클립 2종 + 야간 실촬 3종 전부 통과.
- 판정 비용 자체가 **2초 이내**(정상 영상 처리 시간의 1% 미만).

## 성공 기준

1. `bench.py --smoke`가 green — 합성 암흑 영상 탈락 / 컬러바 영상 통과 / **앞부분만 어두운 영상 통과**
   (중앙값 규칙이 오탐을 막는지)를 실제로 태운다.
2. `server.py --smoke`가 green — 정상 경로(기존 4K 왕복 + `precheck.passed=true`)와
   **탈락 경로**(어두운 영상 업로드 → `DONE` + `highlights=[]` + `precheck.passed=false` →
   `GET /jobs/{id}/video` 409 → `out.mp4` 미생성)를 둘 다 태운다.
3. `precheck_experiment.py`가 `bench.py`의 판정 함수를 import한 뒤에도 `results/MSG-284-report.md`의
   판정 표(PASS 9종 통과 · FAIL 1종 탈락)를 그대로 재현한다 — 오탐 0 · 미탐 0.
4. dev EC2 실측으로 PRD 비기능(판정 ≤2초, 탈락 잡 총 처리 ≤5초)을 확인하고
   `results/MSG-284-report.md`에 기록한다. **macOS 측정은 무효**(CLAUDE.md "알아둘 함정").
5. 기존 응답 필드(`job_id`·`status`·`highlights`·`error`)와 `status` 전이가 그대로다 —
   BE가 `precheck`를 안 읽어도 정상 영상 경로의 동작이 바뀌지 않는다.

## 처리 로직

### 판정 규칙 (정본: `results/MSG-284-report.md`)

grayscale std의 **프레임 중앙값 < 10.0이면 탈락.** 평균이 아니라 중앙값인 이유는 오탐 방지다 —
촬영 시작 직후에만 렌즈가 가려진 영상이 전체 탈락하면 안 된다. 영상 전반이 어두워야 탈락이다.

- PASS 최소 36.69(`night-dark`) / FAIL 최대 3.18(`dark-covered`) 사이. PASS 쪽 3.7배 · FAIL 쪽 3.1배 여유.
- `bright_pct`는 완전분리로 마진이 더 컸지만 `BRIGHT_LEVEL` 같은 자의적 상수를 하나 더 요구해 미채택.
- `lap_var`(선명도 계열)는 **쓰지 않는다** — 센서 노이즈를 엣지로 오인해 방향이 뒤집힌다(PASS 6.52 < FAIL 179.31).
- 정확도 방향이 블러와 반대다: **오탐이 사고, 미탐은 3분 낭비.** 애매하면 통과.

### `bench.py`

상수는 파일 상단 상수 블록(`FACE_CONF` 옆)에 근거 주석과 함께 모은다.

```python
# MSG-284: 프리체크 — grayscale std 중앙값이 이 값 미만이면 탈락(암흑·렌즈 가림).
# 근거는 results/MSG-284-report.md — PASS 최소 36.69 / FAIL 최대 3.18 사이.
# 오탐(정상 영상 탈락)이 사고이고 미탐은 3분 낭비로 끝난다 → PASS 쪽에 넉넉히 붙였다.
PRECHECK_STD_THRESHOLD = 10.0
PRECHECK_FRAMES = 10   # 1080p 0.55초. 20/10/5장에서 std가 ±0.2% 이내라 20장은 낭비다
```

- `sample_frames(path, n)` — `face_experiment.py`에서 그대로 이관(동작 변경 없음).
  못 여는 입력에 `SystemExit`을 던지는 현재 동작을 유지한다 — 워커가 이미 잡는다(FR-8).
- `frame_metrics(frame)` / `video_metrics(path, n_frames)` — `precheck_experiment.py`에서 이관.
  지표 6종을 그대로 옮긴다(판정은 `std`만 쓰지만 나머지는 FR-7 로깅·사후 임계값 조정용이고,
  10프레임 계산이라 비용이 무시할 수준이다). `video_metrics`에 한 줄 가드를 더한다 —
  읽힌 프레임이 0장이면 `SystemExit("프레임을 읽을 수 없음: {path}")`
  (없으면 `IndexError`로 새는데, 원인이 안 드러나는 실패는 FR-8 취지에 어긋난다).
- `precheck(path, n_frames=PRECHECK_FRAMES)` 신설 — 반환:

```python
{"passed": bool, "reason": str | None, "metrics": {...}}   # metrics = video_metrics 결과 6종
```

  `reason`은 탈락일 때만 문자열이고 형식은 `f"too_dark: std {std:.2f} < {PRECHECK_STD_THRESHOLD}"`.
  코드 접두어(`too_dark`)는 BE 매핑용으로 고정, 콜론 뒤 수치는 진단용(FR-7)이라 형식이 바뀔 수 있다.
- `make_dark_video(path, dark_sec=6, bright_sec=0, size=(640, 480), fps=30)` 신설 —
  검은 화면 `dark_sec`초 뒤에 컬러바 `bright_sec`초를 이어 붙인 합성 영상(ffmpeg lavfi
  `color=c=black` + `testsrc`, `bright_sec=0`이면 검은 화면 단독). `bright_sec>0`이 곧
  "촬영 시작 직후에만 가려진 영상"이고, 중앙값 규칙이면 **통과**해야 한다.

### `server.py`

`process()` — `downscale()` 직후에 게이트를 둔다. 탈락이면 `bench.run()`과 오디오 복원 ffmpeg를
둘 다 건너뛰므로 `out.mp4`가 **생성되지 않는다**. 파일이 없다는 사실 자체가 원본 유출 차단이다(FR-6).

```python
downscale(src, scaled)
check = bench.precheck(scaled)
if not check["passed"]:
	# MSG-284: 탈락 잡은 추론·하이라이트·재인코딩을 전부 건너뛴다.
	# out.mp4를 만들지 않는 것이 곧 원본 유출 차단이다 (PRD FR-6)
	return {"highlights": [], "precheck": check}
report = bench.run(scaled, DEVICE, raw)
...
report["precheck"] = check
return report
```

`worker()` — 판정 수치를 stdout으로 남기고(FR-7 — Docker 로그로 수집, 배포 후 임계값 재조정 근거),
잡에는 계약 필드 2개만 저장한다.

```python
check = report["precheck"]
print(f"[precheck] job={job_id} passed={check['passed']} metrics={check['metrics']}", flush=True)
job["precheck"] = {"passed": check["passed"], "reason": check["reason"]}
job["highlights"] = report["highlights"]
job["status"] = "DONE"
```

탈락도 `DONE`이다(FR-5). 예외 처리 `except (Exception, SystemExit)`은 그대로 두고 프리체크 실패도
기존 `FAILED` + `error` 경로를 탄다(FR-8) — 새 실패 모드를 만들지 않는다.

`create_job()` — `jobs[job_id]`에 `"precheck": None` 추가. 기존 `highlights`·`error`와 같은
"판정 전에는 null" 패턴이라 응답 스키마가 상태와 무관하게 일정하다.

`get_video()` — `status != "DONE"` 검사 뒤에 탈락 검사를 추가한다. 탈락 잡은 `DONE`이라
기존 검사만으로는 통과해버리고, 없는 파일에 `FileResponse`가 걸려 500이 난다.

```python
if job["precheck"] and not job["precheck"]["passed"]:
	# 블러본이 없다. 원본을 대신 내보내면 프라이버시 사고다 (PRD FR-6)
	raise HTTPException(409, f"프리체크 탈락: {job['precheck']['reason']}")
```

### `precheck_experiment.py`

이관된 것들을 `bench`에서 가져오고 자체 정의는 지운다 — 실험이 검증하는 대상이 곧 배포되는 코드여야
`results/MSG-284-report.md`가 근거로 유효하다.

```python
from bench import PRECHECK_STD_THRESHOLD, frame_metrics, make_smoke_video, sample_frames, video_metrics
```

- 자체 `STD_THRESHOLD` 상수는 삭제하고 `PRECHECK_STD_THRESHOLD`를 쓴다(임계값 정본은 `bench.py` 하나).
- `--frames` 기본값 **20 유지** — 리포트 표가 20장 측정이라 `python precheck_experiment.py`로 그대로
  재현돼야 한다. 배포는 10장이고 std가 ±0.2% 이내라 판정은 동일하다는 주석을 남긴다.
- `run()`의 `verdict` 계산은 `bench.PRECHECK_STD_THRESHOLD` 기준으로 바뀌는 것 외에는 그대로.

## 계약 변경

**있음 — BE 협의 필요.** BE 레포 경계를 넘는 변경이라 이 레포 안에서 끝나지 않는다.
후속 BE 티켓은 PRD §8이 정의하며 BE 세션에서 발행한다.

| 대상 | 변경 | BE 영향 |
|---|---|---|
| `GET /jobs/{id}` | `precheck: {passed: bool, reason: str\|null}` **추가**. 통과 `{true, null}` / 탈락 `{false, "too_dark: ..."}` / 판정 전 `null` | 없음 — 추가 필드라 무시해도 기존 동작 유지(PRD 비기능 "계약 호환") |
| `GET /jobs/{id}/video` | 탈락 잡에 **409** (`status`는 `DONE`인데 영상이 없는 새 케이스) | **있음.** BE는 `DONE`이면 200을 기대한다 → BE 미적용 상태에서는 해당 잡이 "처리 실패"로 떨어진다. PRD §3 "BE 미적용 상태의 동작"이 이를 명시적으로 수용한다(큐 절감은 즉시 발생, 원본이 나가는 경로는 없음) |
| `status` 전이 | 변경 없음 (`QUEUED → PROCESSING → DONE \| FAILED`) | 없음 |
| 기존 필드 | `job_id`·`status`·`highlights`·`error` 변경 없음. 탈락 잡의 `highlights`는 `[]` | 없음 |

## 검증 시나리오

테스트 프레임워크는 도입하지 않는다(`.claude/rules/project-conventions.md`) — 기존 `--smoke`를 확장한다.

### 1. `./.venv/bin/python bench.py --smoke`

기존 어서션 유지 + 프리체크 항목 추가:

| 검증 | 기대 |
|---|---|
| `frame_metrics` 극단 입력 | 전부 검은/흰 프레임의 `std` < 10 (단색은 대비 0) |
| 노이즈 있는 암흑 프레임 | `std` < 10 — 센서 노이즈가 있어도 탈락해야 한다(리포트의 FAIL 샘플 구성) |
| `precheck(합성 컬러바 영상)` | `passed=True`, `reason is None` |
| `precheck(make_dark_video(dark_sec=6))` | `passed=False`, `reason`이 `"too_dark:"`로 시작하고 std 값을 포함 |
| `precheck(make_dark_video(dark_sec=1, bright_sec=5))` | **`passed=True`** — 앞부분만 어두운 영상은 통과(중앙값 규칙의 오탐 방지가 실제로 동작하는지) |
| `video_metrics` 프레임 0장 | `SystemExit` (FR-8 — 기존 실패 경로) |

### 2. `./.venv/bin/python server.py --smoke`

기존 4K 왕복 유지 + 두 경로를 모두 태운다:

| 단계 | 기대 |
|---|---|
| 정상 4K 합성 영상 업로드 → 폴링 | `DONE`, `highlights` ≤3구간, `precheck == {"passed": true, "reason": null}` |
| 정상 잡 `GET /jobs/{id}/video` | 200, 본문 비어있지 않음, 1920 이하 · 30fps 이하 (기존) |
| `make_dark_video(dark_sec=6)` 업로드 → 폴링 | `DONE`, `highlights == []`, `precheck["passed"] is False`, `reason` 문자열 |
| 탈락 잡 `GET /jobs/{id}/video` | **409** |
| 탈락 잡 잡 디렉터리 | `out.mp4`가 **존재하지 않는다** (FR-6 — 원본이 나갈 파일 자체가 없음) |

탈락 경로에 **처리 시간 어서션은 넣지 않는다** — macOS 측정은 무효다(CLAUDE.md "알아둘 함정").
